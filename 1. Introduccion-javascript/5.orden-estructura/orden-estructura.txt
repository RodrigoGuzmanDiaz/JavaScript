ahora vamos a ver como deberiamos posicionar el script para porder conectar el archivo js a nuestro html
la primera posicion es dentro del <head>
<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>orden y estructura</title>
    <script src="app.js"></script>
</head>
<body>
    <h1>Hola mundo</h1>

    <p>este es un parrafo</p>

    <ul>
        <li>Elemento 1</li>
        <li>Elemento 2</li>
        <li>Elemento 3</li>
    </ul>
</body>
</html>

pero hay que tomar una consideracion que este al momento que el navegador carga nuestra pagina lo que hará el ir linea por liena por lo tanto el <script src="app.js"></script> cargará antes del contenido html que pusimos dentro del <body> por lo tanto no es recomendado posicionarlo asi aun que si es valido ponerlo dentro del <head>
ponerlo dentro del <head> es normal cuando usamos frameworks ya sea de css como bootstrap o tailwind donde necesitamos que este script cargue antes de mostrar el contenido de la pagina
(por favor lista forma en donde es reocmendado poner el script en el head para buenas practicas consejos profecionales y eso)

ahora vamos a ver la segunda forma de posicionar y la reocmendada si trabajamos con archivos.js locales y es antes de la etiqueta de cierre del body es decir, justo antes del </body>
<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>orden y estructura</title>
</head>
<body>
    <h1>Hola mundo</h1>

    <p>este es un parrafo</p>

    <ul>
        <li>Elemento 1</li>
        <li>Elemento 2</li>
        <li>Elemento 3</li>
    </ul>

    <script src="./app.js"></script>
</body>
</html>

recordando que al momento que el navegador cargue la pagina, el navegador lo hace linea por linea lo cual al ponerlo antes de la etiqueta de cierre del </body>, lo que hará es cargar primero el contenido html antes del contenido del archivo js lo que hará que el usuario al menos vea primero la cara de la pagina antes de empezar a interactuar con la pagina
